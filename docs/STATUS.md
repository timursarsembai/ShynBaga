# ShynBaga: состояние проекта

Обновлено 2026-11-08. Файл для следующих сессий: что сделано, как устроено, что дальше. Секретов здесь нет, они только в `.env` на сервере.

## Цель

Бесплатный энтузиастский сервис: история цен на маркетплейсах, чтобы проверить, не подняли ли продавцы цену перед акцией (Kaspi Жұма). Сначала Каспи Магазин, потом другие площадки. Позже сайт, браузерные расширения, мобильные приложения, поиск похожих карточек по фото и описанию.

## Решения владельца

- Название ShynBaga («шын баға», честная цена). Раньше было ShinBaga, переименовано 2026-11-06.
- Архитектура сразу под несколько маркетплейсов.
- Пока только сбор данных. Сайт позже, домена пока нет.
- Стек и категорию выбирает Claude: Python, Postgres, Docker; смартфоны, Алматы.
- Прокси: с 2026-11-08 два собственных статических IP IPRoyal ISP (Польша и Колумбия), купленных для ShynBaga. IP Videoner больше не используется. Казахстанский IP не нужен.
- При блокировке (403, 429, страница проверки) сбор останавливается и не переходит на другой IP.
- Обход каждые 6 часов (решено 2026-11-08).
- Оба IP работают параллельно, каждый со своей паузой 10 секунд, то есть 2 запроса в 10 секунд вместо одного. Это сознательное отступление от `Crawl-delay: 10`, владелец согласился 2026-11-08. При обрыве соединения запрос повторяется через другой IP, следующий запрос снова идёт через свой.
- 3000 смартфонов за обход (с 2026-11-08). Расчёт: около 5,4 часа на обход.
- Бюджет на прокси не определён.
- На будущем сайте показывать только факты о ценах, без обвинений продавцов. Без логотипа Каспи, с пометкой о независимости.

## Как устроено

- `src/shynbaga/marketplaces/` — адаптер на площадку за протоколом `Marketplace`. Сейчас только `kaspi.py`.
- `price_intervals` — отрезок неизменной цены продавца в регионе. Перерыв в наблюдениях больше 48 часов закрывает отрезок.
- `crawl_runs` — журнал запусков со статусом, ошибкой и объёмом трафика.
- Контейнеры `shynbaga-postgres` (порт 5436 только на 127.0.0.1) и `shynbaga-collector` (цикл: обход, если с начала прошлого прошло 6 часов; проверка каждые 10 минут).
- Уведомления о блокировке, падении и неполном обходе идут в Telegram через бот серверных алертов.

Команды (из `~/apps/shynbaga`):

```bash
docker compose up -d --build                                   # выкатить
docker compose logs -f collector
docker run --rm --network host --env-file .env shynbaga check  # два запроса: есть ли доступ
docker run --rm --network host --env-file .env shynbaga lookup 'https://kaspi.kz/shop/p/...'
docker run --rm --network host --env-file .env shynbaga test-alert
docker exec shynbaga-postgres psql -U shynbaga -c "select * from crawl_runs order by id desc limit 5"
```

## Что известно о Каспи

- С IP дата-центра все адреса отдают 429. Через резидентный прокси — 200.
- Список категории: `GET /yml/product-view/pl/results?q=:category:Smartphones&page=N&c=<город>&ui=d&sort=relevance&i=-1`, 12 карточек на страницу, ответ `{"data": [...]}`. В категории смартфонов 8664 товара.
- `/yml/product-view/pl/filters` тяжелее и со страницы 2 отвечает 400. Не использовать для обхода.
- Продавцы товара: `POST /yml/offer-view/offers/{id}`, страницы по 32, в ответе есть `total`.
- Отдельный товар: `GET /yml/content/item/product/{id}`, название в `card.name`.
- ID продавца бывает текстовым (`Sulpak`, `webtrade`). Страница продавца: `/shop/info/merchant/{id в нижнем регистре}/`.
- В названиях продавцов смешивают кириллицу и латиницу (`Sulpаk` с русской «а»). Для поиска по названию нужна нормализация.
- robots.txt: `Crawl-delay: 10` (соблюдаем), `/yml/` не закрыт, есть нестандартный `Visit-time: 0400-0845` (09:00–13:45 по Алматы). 6-часовой график его не соблюдает, см. открытые вопросы.
- Цена в данных — цена предложения продавца, без бонусов и доставки. Список отдаёт ещё `priceMinusBonus`, мы его не сохраняем.

## Цифры

- Обход 1000 товаров: около 3,2 часа, около 18 МБ трафика, примерно 1,1 запроса на товар.
- 2026-11-06: 972 товара, 28 пропущены из-за 8-минутного сбоя прокси.
- 2026-11-07: оборвался на 135 товарах из-за одного сбоя соединения на странице списка. После этого добавлены повторы (30 с, 1, 2, 5 мин) и остановка после 5 неудачных товаров подряд.
- 2026-11-08: запуск №6, первый с повторами и графиком каждые 6 часов. 1000 из 1000 товаров без ошибок, 3 ч 08 мин, 17,7 МБ. Повторы не понадобились.
- 2026-11-08: запуск №7 упал на 694 товарах. Прокси обрывал соединения примерно 30 раз в час, повторы справлялись, но одно оборванное соединение застряло в пуле httpx, и дальше все запросы падали с `PoolTimeout`. Исправлено: после каждого временного сбоя клиент создаётся заново. Брошенные записи `running` теперь закрываются при старте сборщика.
